AMD HLS SkillsHuman direction
So I says to the agent, I says
“We have up to 2,000 cycles between samples. Stop optimizing cycle count. We absolutely must reach timing closure.”
Change the objective · change the design
This is the central human contribution in the story. The engineer understood the system-level budget and redirected the optimization objective. The right question was not “How few cycles?” It was “How much sequential work can we spend to shorten the longest path?”

The concrete first fix split the serial sixteen-deep floating-point recurrence into four independent partial accumulators, then combined them through a two-level tree. Similar reasoning guided the richer implementation: use available cycles to prevent too much work converging into one clock period.

Vitis AI HLSPS / PL boundary
Put each kind of work where it belongs

Events in software. Samples in fabric.

Processing system

Policy

ALSA receives MIDI. C allocates voices, translates controls and writes only changed state over AXI4-Lite.

Programmable logic

Determinism

RTL adopts a coherent snapshot, schedules HLS once per sample and transfers stable PCM into the I2S clock domain.

Commit generation publishes state atomically
This is the required PS-to-PL emphasis. Software writes voice and parameter shadows, then writes a commit generation last. At an audio request, PL adopts the complete bank only when the generation changes. Audio never streams from Linux.
